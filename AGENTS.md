# UH Homes Selections

- A Flask app backed by one master `.xlsx` workbook, in one of two modes chosen purely by environment variables: local (a file beside the app, no accounts, bound to `127.0.0.1`) or hosted (the workbook in Supabase Storage, sign-in required). Default to local; keep both paths working.
- On Windows, run `.venv/Scripts/python.exe app.py` (or add `--port 5001` if port 5000 is occupied; do not stop unrelated services). Install runtime dependencies with `.venv/Scripts/python.exe -m pip install -r requirements.txt`.
- Core verification: `.venv/Scripts/python.exe -m unittest test_workflow test_auto_lookup test_custom_fields test_hosting -v`, `node --check ui.js`, and `.venv/Scripts/python.exe -m pip check`.
- Browser verification: install `requirements-dev.txt`, then run `.venv/Scripts/python.exe -m unittest test_browser -v`. The browser test uses installed Microsoft Edge through Playwright, runs against a temporary workbook, and saves screenshots under `output/`.
- Do not run `build_tracker.py` against the working master workbook; it overwrites it with example data. Tests must use temporary copies of the workbook.
- Web edits go through `WorkbookStore`, which validates headers, detects stale revisions, backs up the existing workbook, and atomically replaces it. Close Excel before saving through the app.
- `WorkbookStore` owns validation, the `ensure_*` repairs and the price-schedule rebuild; a backend owns only bytes, revisions, backups, history and the lookup-state blob. `LocalBackend` (in `workbook_store.py`, so tests can patch `workbook_store.os.replace`, `workbook_store.workbook_open_elsewhere` and `workbook_store.BACKUP_KEEP`) keeps the file-on-disk behaviour; `SupabaseBackend` is in `supabase_store.py`. Add storage features to the backend interface, not to the routes.
- Hosted saves upload a new immutable `versions/<stamp>.xlsx` object and then advance the single `uh_workbook_state` row with a filtered PostgREST `PATCH`, so the compare-and-swap — not the revision pre-check — decides who wins. If the pointer update fails, delete both the object and its version row so nothing unreachable is offered as a restorable copy. Earlier versions *are* the backups; `backups()` excludes the live revision to match the local folder.
- Local saved copies are ordered by the microseconds in their filenames, never by second-precision timestamps or filesystem mtime: several saves land within one second and "restore the newest copy" must be exact.
- The hosted backend caches the pointer row for `UH_REVISION_TTL` (1s) because the UI polls every 2.5s; a stale read can only cause a rejected save, never a lost one. `AutoLookup` ticks every 10s when remote instead of 2s. Never cache in a way that lets a save bypass the compare-and-swap.
- `common.Sheet.set(row, header, None)` is a silent no-op, because openpyxl's `ws.cell(..., value=None)` does not write. Use `workbook_store.put` to clear a cell.
- Talk to Supabase with `requests` over the Storage and PostgREST REST APIs, matching the project's no-heavy-dependencies style; do not add `supabase-py`. Never let a key or a response body reach an error message, a log or an API response.
- Sign-in is server-side only: `auth.sign_in` posts to Supabase Auth and the browser gets nothing but a signed Flask session cookie, never an access token. The app always reaches Postgres with its own service key. Accounts are created by an administrator (`python auth.py <email>…`, or the dashboard); there is deliberately no sign-up, password reset or email delivery.
- `python supabase_store.py check` is the hosting pre-flight: tables, bucket privacy, seeded workbook, missing variables. Keep it accurate when adding hosting requirements, and keep it free of secret values.
- `deploy_render.py` creates or updates the Render service from `.env`, so settings live in one place. `UH_TRUSTED_HOSTS` must be written after creation, because the hostname is only known then and a wrong value makes every request 400. It must keep sending `numInstances: 1`. Add any new hosted setting to its `COPIED` list, and to `REQUIRED` if the app cannot start without it.
- The CSRF token is per-session when signed in and per-process (`TOKEN`) when running locally, both sent as `X-UH-Token`. Signing in clears the session, so any pre-login token must stop working. Add new routes to `OPEN_ENDPOINTS` only if they are genuinely safe unauthenticated.
- `check_exposure()` runs at import and refuses to start when `UH_HOST` is non-local without sign-in, `UH_SECRET_KEY` and `UH_TRUSTED_HOSTS`. Never weaken that: it is what stops a misconfigured deploy from publishing client selections and pricing.
- The hosted app must run as exactly one process (`wsgi.py` with `waitress-serve --threads=8`). `AutoLookup` is an in-process thread and saves rewrite the whole workbook, so a second worker would race the first. Scale with threads, never instances.
- Never overwrite unchanged Verified products through automated lookup. Item/product name, manufacturer, model, or finish changes invalidate prior metadata and verification, including changes saved directly in Excel.
- `AutoLookup` runs from `app.py` (via `start_automation()`, called by `wsgi.py` when hosted), persists hashed input history and pending results through `store.state()` — `lookup_state/` locally, the `uh_lookup_state` table when hosted — and shares the workbook lock with API edits. Detect row relocations without rechecking unchanged products; acknowledge auto-filled product names so they do not trigger loops. Network calls must run outside the workbook lock, and their results must be revalidated against current product identity before saving.
- App exports must observe changes and block pending rows (or omit them in verified-only mode), even before the worker has cleared old URLs on disk. Test watcher behavior with temporary workbooks and mocked search providers.
- Live search uses a locally configured API key in `.env`; tests mock provider calls. Do not log provider exception URLs or expose keys in API responses.
- The client deliverable is the approved finish schedule kept at `brand_assets/finish_schedule_template.pdf`: letter portrait, 46.8pt side margins, content 518.4pt wide, header rule at y=720, footer rule at y=44.64, flowing content between y=696 and y=56; Lato 8/9/9 for the code/item/description columns (50.4 / 144 / rest) with 6pt horizontal and 6.5pt vertical cell padding, leadings 12/11/11.5, `MIDDLE` cell alignment, and letter-spaced section headings 15.84pt tall whose rule starts 10pt after the text and ends `HEADING_OVERHANG` (6pt) past the right margin at x=571.2, matching the template. `test_workflow.ScheduleTests.test_layout_matches_the_approved_template` rebuilds that page and compares every text baseline and rule against the reference, normalising only the template's placeholder band values. Keep that test green rather than eyeballing layout changes.
- `Unit Price` is an optional numeric Selections column; `put` writes `Qty` and `Unit Price` as real numbers so Excel's `SUM`/`ISNUMBER` work. The `Price Schedule` sheet (`price_schedule.rebuild`, run from `WorkbookStore.save`) is a generated view, never an input: selections grouped by project then category with S.No, Code, Description, Qty, Unit Price and Price as live formulas against Selections, plus category subtotals, project totals and a grand total. Pricing is internal and must never appear in client PDFs or PowerPoints.
- Client PDFs and PowerPoints are text only: no product images, no hyperlinks, no cover or closing pages. Product URLs and images stay internal review aids. Keep row descriptions derived from workbook columns (manufacturer, product name or model, finish, quantity when not 1, client notes) and never print internal lookup status outside `--draft`.
- PDF and PowerPoint generators share branding, fonts, geometry constants and row/description helpers from `lookbook_config.json` and `build_lookbook.py`. Both accept an explicit output directory plus a per-export schedule `title` and item code `prefix` (validated in `app.py`, defaults in `lookbook_config.json`'s `schedule` block). PowerPoint slides are letter portrait at 1pt-per-point parity; page breaks may differ from the PDF by the final block.
- Importing a workbook that Excel has re-saved silently drops the Selections dropdowns: Excel rewrites list validations into the `extLst` form, and openpyxl warns `Data Validation extension is not supported and will be removed`. `WorkbookStore.save` runs `ensure_validations`, which re-adds the four lists (`B` Section from `Lists!$A$2:$A$31`, `L` Lookup Status from `Lists!$B$2:$B$7`, `P` Include in Lookbook from `Lists!$C$2:$C$3`, `A` Project ID from `Projects!$A$2:$A$51`, each from row 2 through at least row 501) on every save, so app writes repair the loss; only purely-manual Excel edits remain at risk. Prefer the app's own forms over Excel round-trips for data entry.
- Stop `app.py` before writing to the master workbook from a separate process. `WorkbookStore`'s lock is a per-process `threading.RLock`, so locally cross-process safety rests only on the revision hash; hosted, the Postgres compare-and-swap makes it atomic. Excel locking (`workbook_open_elsewhere`) is meaningful only for the local backend.
- `POST /api/workbook/import` and other mutating routes require the `X-UH-Token` header carrying the per-start token rendered into `ui.html`; without it they return 403 `This page has expired.`
- `Client Status` (Proposed / Presented / Approved / Rejected / Changed) is a per-selection *client-approval* lifecycle, deliberately separate from `Lookup Status` (link verification). The column is optional in the workbook schema and added on save by `ensure_selection_columns`; editing identity fields returns Presented/Approved rows to `Changed` and Rejected rows to `Proposed`. Every presentation export is logged in `backups/history.jsonl` and numbered `R{n}` per project in the filename and document metadata; non-draft exports mark included Proposed rows `Presented`. Verified links older than `STALE_DAYS` (180) surface as `Re-check` flags in the UI. `POST /api/selections/parse-link` prefills a selection from a product URL via `find_urls.describe_page`.
- Project/selection custom fields are stored per record in an optional `Custom Fields` JSON column, not global field definitions. Preserve absent custom-field payloads; an explicit empty list clears fields. Validate names and values, keep Excel autofilters inclusive of the extra column, and never include custom metadata in product-lookup identity. App and CLI presentations share `presentation_details` for paginated additional details.
- Supplied logos live in `brand_assets/`, brand fonts (Lato, SIL OFL with its license file) in `brand_assets/fonts/`. Use `branding.load_logo` to retain PNG transparency. Use the white/gold wordmark (`logo_path`) on dark backgrounds such as the app sidebar, the dark print wordmark (`logo_print_path`) on the white schedule pages, the gold symbol for compact branding, and always preserve aspect ratio.
- The Client presentations panel mirrors the deliverable: `ui.js` builds a live paper preview from the selected project's rows with the same description helper, so keep `rowDescription` in `ui.js` in step with `description` in `build_lookbook.py`.
