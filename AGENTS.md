# UH Homes Selections

- A Flask app backed by one master `.xlsx` workspace, in one of two modes chosen purely by environment variables: local (a file beside the app, no accounts, bound to `127.0.0.1`) or hosted (the workspace in Supabase Storage, sign-in required). Default to local; keep both paths working.
- On Windows, run `.venv/Scripts/python.exe app.py` (or add `--port 5001` if port 5000 is occupied; do not stop unrelated services). Install runtime dependencies with `.venv/Scripts/python.exe -m pip install -r requirements.txt`.
- Core verification: `.venv/Scripts/python.exe -m unittest test_workflow test_custom_fields test_hosting -v`, `node --check ui.js`, and `.venv/Scripts/python.exe -m pip check`.
- Browser verification: install `requirements-dev.txt`, then run `.venv/Scripts/python.exe -m unittest test_browser -v`. The browser test uses installed Microsoft Edge through Playwright, runs against a temporary workspace, and saves screenshots under `output/`.
- Do not run `build_tracker.py` against the working master workspace; it overwrites it with example data. Tests must use temporary copies of the workspace.
- Web edits go through `WorkspaceStore`, which validates headers, detects stale revisions, backs up the existing workspace, and atomically replaces it. Close Excel before saving through the app.
- `WorkspaceStore` owns validation, the `ensure_*` repairs and the price-schedule rebuild; a backend owns only bytes, revisions, backups and history. `LocalBackend` (in `workspace_store.py`, so tests can patch `workspace_store.os.replace`, `workspace_store.workspace_open_elsewhere` and `workspace_store.BACKUP_KEEP`) keeps the file-on-disk behaviour; `SupabaseBackend` is in `supabase_store.py`. Add storage features to the backend interface, not to the routes.
- Hosted saves upload a new immutable `versions/<stamp>.xlsx` object and then advance the single `uh_workbook_state` row with a filtered PostgREST `PATCH`, so the compare-and-swap — not the revision pre-check — decides who wins. If the pointer update fails, delete both the object and its version row so nothing unreachable is offered as a restorable copy. Earlier versions *are* the backups; `backups()` excludes the live revision to match the local folder.
- Local saved copies are ordered by the microseconds in their filenames, never by second-precision timestamps or filesystem mtime: several saves land within one second and "restore the newest copy" must be exact.
- The hosted backend caches the pointer row for `UH_REVISION_TTL` (1s) because the UI polls every 2.5s; a stale read can only cause a rejected save, never a lost one. Never cache in a way that lets a save bypass the compare-and-swap.
- `common.Sheet.set(row, header, None)` is a silent no-op, because openpyxl's `ws.cell(..., value=None)` does not write. Use `workspace_store.put` to clear a cell.
- Talk to Supabase with `requests` over the Storage and PostgREST REST APIs, matching the project's no-heavy-dependencies style; do not add `supabase-py`. Never let a key or a response body reach an error message, a log or an API response.
- Send keys through `auth.key_headers`. The newer `sb_publishable_…`/`sb_secret_…` keys are opaque strings, not JWTs, so they go on `apikey` only; legacy `anon`/`service_role` JWTs go on both `apikey` and `Authorization`. Keep the client's `User-Agent` non-browser-like: Supabase rejects secret keys that look like they came from a browser.
- A half-filled `.env` means "not configured yet", not an error: `settings()` returns `None` so the local app keeps running mid-setup. The dangerous combination — a non-local `UH_HOST` serving a local workspace file, which a redeploy would discard — is refused by `check_exposure()` instead.
- Sign-in is server-side only: `auth.sign_in` posts to Supabase Auth and the browser gets nothing but a signed Flask session cookie, never an access token. The app always reaches Postgres with its own service key. Accounts are created by an administrator (`python auth.py <email>…`, or the dashboard); there is deliberately no sign-up, password reset or email delivery.
- `python supabase_store.py check` is the hosting pre-flight: tables, bucket privacy, seeded workspace, missing variables. Keep it accurate when adding hosting requirements, and keep it free of secret values.
- `deploy_render.py` creates or updates the Render service from `.env`, so settings live in one place. `UH_TRUSTED_HOSTS` must be written after creation, because the hostname is only known then and a wrong value makes every request 400. It must keep sending `numInstances: 1`. Add any new hosted setting to its `COPIED` list, and to `REQUIRED` if the app cannot start without it. It then asks Render for a deploy by name: an environment change rebuilds only when a value actually changed, and a push only while Render's GitHub connection is live, so neither ships a commit reliably. The host once served code three commits old, which rejected the workspace for missing the retired lookup columns that version still required — a stale host and a current workspace is what that class of error looks like. It happened again, twice in one day, with `autoDeploy` reading `yes` the whole time: a corrected footer and then a new column were both live in `main` and absent from the site, so each looked like a bug that had not been fixed. `.github/workflows/deploy.yml` now asks for the deploy from GitHub on every push to `main`, gated on a `RENDER_SERVICE_ID` repository *variable* (a secret cannot be read in an `if`, and a missing variable must skip rather than fail every push) with `RENDER_API_KEY` as a secret. It ships code only; environment values still belong to `deploy_render.py` and `.env`. When a report and the code disagree, check which commit the host is on before reading the code again.
- A 502/503/504 is the host's router, not the app: the hosted workspace is deliberately one process, so a deploy or a restart leaves a few seconds with nothing behind the address, and a save or a poll caught in that gap used to read `Request failed (502)` as if the workspace had refused it. `ui.js`'s `api` retries a *read* through `GATEWAY_WAITS` (0.7s, 2s, 4.5s), which covers the 2.5s poll and every `refresh`. It must never retry a write: `delete` names a row by its number and the editor creates rows, so a second attempt could remove the wrong line item or add a duplicate — the message says the app is restarting and the edit stays held for Save, which already retries. `test_browser.test_a_restarting_host_is_waited_out_rather_than_reported` pins both halves.
- The CSRF token is per-session when signed in and per-process (`TOKEN`) when running locally, both sent as `X-UH-Token`. Signing in clears the session, so any pre-login token must stop working. Add new routes to `OPEN_ENDPOINTS` only if they are genuinely safe unauthenticated.
- `check_exposure()` runs at import and refuses to start when `UH_HOST` is non-local without sign-in, `UH_SECRET_KEY` and `UH_TRUSTED_HOSTS`. Never weaken that: it is what stops a misconfigured deploy from publishing client selections and pricing.
- The hosted app must run as exactly one process (`wsgi.py` with `waitress-serve --threads=8`), because a save rewrites the whole workspace and a second worker would race the first. Scale with threads, never instances.
- There is deliberately no product lookup and no link verification of any kind: no search provider, no `Add from link`, no `Lookup Status`, no `Checked On`, no stale/`Re-check` flag and no `Verified` state. `Product URL` is typed or pasted by the person specifying the home and is simply present or absent. Do not reintroduce a background worker, a search API key, a `/api/selections/<row>/lookup` route or a status column, and do not add a `confirm_verified` argument back to `merge_selection`.
- `Lookup Status`, `Checked On` and `Lookup Notes` on Selections, plus `Links Found`, `Verified` and `Needs Review` on Projects, are listed in `RETIRED_SELECTION_FIELDS` / `RETIRED_PROJECT_FIELDS`. `records` hides them so a workspace saved before they went reads back like one saved after, and `drop_retired_columns` (first step of `WorkspaceStore.save`) deletes them for good. Deleting shifts every column to its right, which openpyxl does not follow through to list validations or hyperlinks, so that function clears both and lets `ensure_validations` and `ensure_product_links` rebuild them from the surviving headers. Lists column B is emptied rather than deleted, because the Yes / No, Client Status and Locations ranges name columns C, D and E by letter. They stay in `common.AUTO_OR_FORMULA` so a stray leftover value cannot make an empty row look occupied before that save happens.
- The only generated documents are the spec sheets (`build_lookbook.build_spec` for PDF, `build_word.build_spec` for Word) and the spec-sheet CSV. The finish-schedule, fillable and PowerPoint builders (`build_lookbook.build`, `build_form`, `build_word.build_fillable`, `build_powerpoint`) remain as command-line tools and are deliberately not reachable from the app.
- The workspace itself is never downloaded or uploaded through the app: there is no `/api/workspace`, no workspace import and no backup/restore route. Earlier copies are still written before every save and restored with `WorkspaceStore.backups()`/`read_backup()`/`import_bytes()` from a script or a test.
- The spec-sheet exports mirror the app's spec-sheet table exactly, column for column: `build_lookbook.SPEC_COLUMNS` is Item, Manufacturer, Model #, Finish / Color, Product Link, Qty, Unit Price and Markup %, and it must stay in step with `SPEC_COLUMNS` in `ui.js`. `spec_groups` puts the rows under the heading the view is grouped by, passed as `group` (`Room / Area` or `Section`, validated in `app.py` and sent by `specQuery`), so a download reads like the screen it came from. Reading like the screen also means *in the screen's order*: `spec_export_rows`, the spec CSV and `spec_rows` hand over line items in plain workspace order and must never `schedule_sort` them, because the view is workspace order and dragging a row on the spec sheet writes that order back. Sorting the rows by Location instead moved twelve of thirteen headings and scrambled the rows inside them, so a row dragged into place landed somewhere else in its own PDF; `test_spec_exports_keep_the_order_the_view_shows` pins the CSV, PDF and Word order to the sheet. The view's two group-by chips are By room — `state.specGroup`'s default, and so `group_option`'s and every `build_spec`'s — and By category; grouping the spec sheet by Location was removed by request, so `SPEC_GROUPS` refuses it like any other unknown name. The finish schedule's own `group_sections` still prints Location headings, which is a different function and stays.
- The client deliverable is the approved finish schedule kept at `brand_assets/finish_schedule_template.pdf`: letter portrait, 46.8pt side margins, content 518.4pt wide, header rule at y=720, footer rule at y=44.64, flowing content between y=696 and y=56; Arial 9/10/10 for the code/item/description columns (50.4 / 144 / rest) with 6pt horizontal and 6.5pt vertical cell padding, leadings 13/13/13, `MIDDLE` cell alignment, and letter-spaced section headings 15.84pt tall whose rule starts 10pt after the text and ends `HEADING_OVERHANG` (6pt) past the right margin at x=571.2, matching the template. `test_workflow.ScheduleTests.test_layout_matches_the_approved_template` rebuilds that page and compares every text baseline and rule against the reference, normalising only the template's placeholder band values. The footer symbol is the one piece of that furniture the test cannot see, because an image is neither a baseline nor a rule: `mark_bottom` centres it on the contact line's cap middle (`FOOT_BASE` plus half the cap height) instead of standing it on the baseline, where it sagged below the words, and Word lowers its inline copy by the same offset with `w:position` over an at-least line so the symbol is not clipped. The contact line's own baseline and `CONTACT_X` are pinned by the template, so only the symbol may move. Keep that test green rather than eyeballing layout changes.
- `Unit Price` is an optional numeric Selections column; `put` writes `Qty` and `Unit Price` as real numbers so Excel's `SUM`/`ISNUMBER` work. The `Price Schedule` sheet (`price_schedule.rebuild`, run from `WorkspaceStore.save`) is a generated view, never an input: selections grouped by project then category with S.No, Code, Description, Qty, Unit Price and Price as live formulas against Selections, plus category subtotals, project totals and a grand total. Pricing is internal and must never appear in the client PDF, Word or PowerPoint copies; the spec sheets (`build_word.build_spec` and `build_lookbook.build_spec`, Word and PDF) are the only generated documents that show it.
- Client documents stay text only except one deliberate image: when a project's `Cover Image` holds an image, the exported PDF opens with a cover page (brand header, the rendering in a hairline frame, project and client centred below). Word, PowerPoint and fillable copies have no cover page. A `cover:<name>` cell value points at a file the app stored via `WorkspaceStore.store_cover`/`read_cover` — `./covers/` locally, `covers/` objects in the hosted bucket — set by `POST /api/projects/<pid>/cover` (PIL-normalised PNG/JPEG) and served back by the matching `GET`. URLs and file paths still work through `build_lookbook.resolve_cover`, which refuses non-public addresses before fetching. Product images stay internal review aids and there are still no closing pages. Keep row descriptions derived from workspace columns (manufacturer, product name or model, finish, quantity when not 1, client notes).
- Every schedule row that has a `Product URL` ends in a clickable `Product Link` — `build_lookbook.link_markup` for the PDF, a hyperlinked run in the PowerPoint and in Word, the same words in all three. This was requested deliberately and reverses the earlier "no hyperlinks in client deliverables" rule; only images and pricing remain internal. The fillable copies are the exception: their descriptions are editable fields compared against `description` on import, so a link there would read back as a hand-reworded line. `ui.js`'s paper preview appends the same link, and `rowDescription` must stay in step with `description` (which itself stays link-free, because `build_form`, `build_word` and `price_schedule` reuse it). `product_link` honours a hidden `Product URL` column.
- `Product Link` is a generated Selections column, never an input: `ensure_product_links` rewrites it on every save so the cell reads "Product Link" and hyperlinks to that row's `Product URL`, and `records` hides it so a workspace saved before the column existed reads back the same shape. Both the app and the CSV import still write `Product URL`; the app's spec-sheet `PRODUCT LINK` column is bound to that field too. Add generated columns to `GENERATED_SELECTION_FIELDS` and to `common.AUTO_OR_FORMULA`, or an orphan value will make an empty row look occupied.
- The spec-sheet CSV carries `Product Link` as `=HYPERLINK("<url>","Product Link")`, emitted only for a validated http(s) URL so the leading `=` is never user text. Excel re-saves a CSV with the formula's *displayed* text, so `csv_values` treats a cell it cannot read an address out of as "unchanged", never as "clear this link"; an address that differs from the stored one replaces it.
- PDF, Word and PowerPoint generators share branding, fonts, geometry constants and row/description helpers from `lookbook_config.json` and `build_lookbook.py`. All accept an explicit output directory plus a per-export schedule `title`, item code `prefix` and `hidden` columns (validated in `app.py`, defaults in `lookbook_config.json`'s `schedule` block). PowerPoint slides are letter portrait at 1pt-per-point parity; page breaks may differ from the PDF by the final block.
- Any column a client document shows can be left out of one export, from none to all of them. `build_lookbook.HIDEABLE_COLUMNS` is the single registry: keys are workspace columns, except the generated `code` and `details` blocks, and each entry declares whether it reaches the `schedule` documents, the `sheet` ones, or both. `hidden_columns` accepts a list or a comma-separated string and refuses an unknown name rather than ignoring it, because silently printing a field the user believes they hid is the one unacceptable outcome. `row_widths`, `item_cell`, `group_sections` and `spec_groups` hand a hidden column’s space to the description and drop section headings outright; a `Description Override` still prints as typed, being literal text rather than columns. The app reaches this only through the spec-sheet downloads' `hide` query parameter; hiding Location, Room / Area or Item leaves a spec sheet that cannot be matched back to its rows on import.
- Every export is set in the studio's cream/gold palette, by request: `lookbook_config.json`'s `colors` hold the app's own values (`#FAF8F1` paper, `#F4EEE1` band, `#E8E1D0` hairlines, `#AA8960` rules, `#8D7342` accent, `#2E2A1F` ink), and all three builders read them, so one edit there moves the PDF, Word and PowerPoint together. `build_lookbook.paper` lays the cream sheet under each page because reportlab leaves paper white; PowerPoint sets a slide background; Word needs a `w:background` *plus* `w:displayBackgroundShape`, and even then Word prints a page colour only when "Print background colors and images" is on. This deliberately overrides the approved template's white paper — the signed-off *geometry* still rules, and `page_geometry`/`test_layout_matches_the_approved_template` compares only text baselines and rules, so colour changes are invisible to it. Keep it that way: never let a colour decide a position.
- A section heading is paired with its rows by `build_lookbook.section_block`, not by reportlab's `keepWithNext`: that keeps a heading with the *whole* table, so any section longer than a page moved itself to the next sheet and left the page it came from empty under the client band. `KeepTogether(..., maxHeight=<frame height>)` splits the rows in place and breaks the page only when the heading itself will not fit. `Heading(keep=False)` exists for that wrapper; standalone headings (`detail_flowables`) keep the plain `keepWithNext`.
- A running `app.py` serves old exports and old HTML until it is restarted: `debug=False` means Jinja compiles `ui.html` once per process, and the export modules are imported at start. `ui.js`/`ui.css` are re-read per request, so they only need a browser reload. Restart the app after touching `ui.html`, `lookbook_config.json` or any `build_*.py`.
- `build_word.py` is the Word twin, and it is *flowed*, not placed: the page keeps the approved geometry, type sizes and column widths, but every block is a real Word paragraph or table so Word repeats the header/footer, reflows edited text and repaginates itself. Section rules are underscore tab leaders, the DRAFT mark is a VML header watermark, and font sizes are read off `build_lookbook`'s reportlab styles so one change moves every deliverable. Page breaks will not match the PDF — do not write tests that assume they do. Never emit two adjacent tables: Word merges them into one.
- Importing a workspace that Excel has re-saved silently drops the Selections dropdowns: Excel rewrites list validations into the `extLst` form, and openpyxl warns `Data Validation extension is not supported and will be removed`. `WorkspaceStore.save` runs `ensure_validations`, which re-adds the lists (`B` Section from `Lists!$A$2:$A$31`, Location wherever its column sits from `Lists!$E$2:$E$31`, Include in Lookbook from `Lists!$C$2:$C$3`, Client Status from `Lists!$D$2:$D$6`, `A` Project ID from `Projects!$A$2:$A$51`, each from row 2 through at least row 501) on every save, so app writes repair the loss; only purely-manual Excel edits remain at risk. Prefer the app's own forms over Excel round-trips for data entry.
- **Unit** is what a `Qty` counts — `EA`, `sq ft`, `SQ` (roofing squares), `LF`, `gal`, `lot` — and an optional free-text Selections column, because the unit follows the trade and no list can name them all. `ensure_unit_list` seeds the `Units` column on Lists for the dropdown and then leaves it to the user, exactly like Locations; both now go through the shared `named_list`/`ensure_named_list` pair. That column is *appended* to Lists rather than given a letter, so `ensure_validations` reads its range off wherever it landed (`Lists!$F$2:$F$31` today) instead of naming it in `LIST_VALIDATIONS` — the C/D/E ranges are hardcoded and must stay that way. Unit is registered in `HIDEABLE_COLUMNS` for the `sheet` family only: the client documents say a quantity in words through `description`, which the fillable copies compare against on import, so adding a unit there would read back as a hand-reworded line. It sits immediately after `Qty` in `build_lookbook.SPEC_COLUMNS`, `SPEC_COLUMNS` in `ui.js` and `app.SPEC_CSV_FIELDS`, and the editor offers it as a dropdown-with-`Other` fed by `/api/state`'s `units`.
- **Location** is where in the home a selection goes (1st Floor, 2nd Floor…); **Section** is only the trade category (Kitchen, Flooring…). Location is an optional Selections column backed by the user-owned `Locations` column on Lists (seeded once by `ensure_location_list`, never rewritten after); `common.location_order`/`schedule_sort` order the finish schedule by it — and only that document, which is the one printing Location headings through `group_sections`; the spec sheet and its downloads stay in workspace order. `WorkspaceStore.save` runs `ensure_locations`, which moves any Section that names a location onto Location, re-infers that row's category via `infer_category(room, item)`, and strips location names from the sections list — so rows seeded before the split migrate themselves on the next save. `spec_template.json` is outline of location → room → item; `spec_template.apply` writes Location plus the inferred Section, and CSV/spec-sheet rows are matched on (Location, Room / Area, Item).
- In the selection editor, **Section** and **Location** are the two dropdowns whose list cannot name every home, so each ends in `Other` — and `Other` is not a value, it means "not on this list": `ui.js`'s `choiceControl` gives way to a blank box (`choiceMode`, with `Choose from the list`/`Enter another value` as the way back), and `editorValues` reads whatever was typed. A stored value the list does not hold reopens in that box, a box left empty keeps the record's existing value (`data-original`), and the inactive control is `disabled` so only the one on screen is submitted. The typed value is saved on that line item alone: nothing is added to the Lists sheet, by request. Do not extend this to `Client Status` or `Include in Lookbook` — the approval lifecycle (`merge_selection`) and the export filter depend on their exact values — and do not re-add the stored value to `choices`, which would turn a typed section back into a dead dropdown entry. `test_browser.test_other_hands_a_dropdown_over_to_a_typed_value` covers the round trip.
- Every modal in the app is a native `<dialog>` opened with `showModal()`, and all four — the record editor, Settings, Import & export and the cover lightbox — dismiss the same three ways: the `×`/Cancel buttons (`.close-dialog`, left enabled while busy), Escape, and a click outside. The last one is `ui.js`'s `backdropOf`, which measures the pointer against the dialog's box rather than trusting `event.target`: a click on the dialog's own 28px padding also reports the dialog as the target and must *not* close it. It also requires the press to have started outside, so dragging to select text in a field and releasing past the edge does not throw away a half-filled form. Any new dialog gets this for free; do not special-case one. `test_browser.test_clicking_away_from_a_dialog_closes_it` covers all three cases.
- Stop `app.py` before writing to the master workspace from a separate process. `WorkspaceStore`'s lock is a per-process `threading.RLock`, so locally cross-process safety rests only on the revision hash; hosted, the Postgres compare-and-swap makes it atomic. Excel locking (`workspace_open_elsewhere`) is meaningful only for the local backend.
- Mutating routes require the `X-UH-Token` header carrying the per-start token rendered into `ui.html`; without it they return 403 `This page has expired.`
- `Client Status` (Proposed / Presented / Approved / Rejected / Changed) is the one status a selection carries: a per-selection *client-approval* lifecycle. The column is optional in the workspace schema and added on save by `ensure_selection_columns`; editing identity fields returns Presented/Approved rows to `Changed` and Rejected rows to `Proposed`, and clears `Product URL` and `Image URL` because they described the previous product.
- The spec sheet's column widths belong to the person reading it: each header carries a `.col-grip` whose drag — or arrow keys, or double-click to reset — sets that column's width, and `table-layout:fixed` plus a `<col>` per field makes the width that was set the width that is used, with whatever is left over past the last column going to the actions cell. One `specWidths` map drives every group card, so the sheet stays a single grid, and it is kept in `localStorage` under `uh-spec-widths`: it describes nobody's home, so it never reaches the workspace. Widths are written through the CSSOM by `applySpecWidths` (from `renderSpec`, and from every drag), never as a `style` attribute — the app's CSP sets `style-src 'self'`, so an inline style in rendered HTML is dropped on the floor without an error, and writing onto the live tables is also what lets a drag resize columns without tearing down the rows being sized. `render`/`renderSpec` defer while `specResize` is set, exactly as they do mid row-drag. `test_browser.test_a_column_width_set_from_its_header_is_kept` covers the drag, the shared grid and the reload.
- Project/selection custom fields are stored per record in an optional `Custom Fields` JSON column, not global field definitions. Preserve absent custom-field payloads; an explicit empty list clears fields. Validate names and values, keep Excel autofilters inclusive of the extra column, and never include custom metadata in the `IDENTITY_FIELDS` comparison. App and CLI presentations share `presentation_details` for paginated additional details.
- Supplied logos live in `brand_assets/`, brand fonts in `brand_assets/fonts/` — PDFs embed Liberation Sans (SIL OFL, metric-identical to Arial, with its LICENSE) while PowerPoints and Word copies name `Arial` via the `fonts.family` config key; Lato is kept for reference. Use `branding.load_logo` to retain PNG transparency. Use the white/gold wordmark (`logo_path`) on dark backgrounds such as the app sidebar, the dark print wordmark (`logo_print_path`) on the white schedule pages, the gold symbol for compact branding, and always preserve aspect ratio.
